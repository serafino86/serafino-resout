# Stella, démo Charte Vaud

La page `site/charte-vaud/index.html` envoie les questions à `https://bot.serafino-resout.ch/api/charte-vaud-chat`. Le serveur Node utilise `GEMINI_API_KEY` côté serveur et, par défaut, le modèle `gemini-3.8-flash` (`STELLA_GEMINI_MODEL` peut le remplacer). La voix est générée par `gemini-3.8-flash-tts` avec une diction française claire via `/api/charte-vaud-voice`, puis lue avec Web Audio ; la dictée dépend du navigateur. L'API vocale ne lit que les réponses émises par le bot ou les fiches publiques, avec cache et limite de 100 générations par jour. Cette démo marketing ne doit pas recevoir de données personnelles ou de commandes réelles dans le chat.

Après **l'envoi effectif** du courriel à Bays, noter son horodatage exact avec fuseau horaire et lancer `node bot/scripts/arm-stella-window.js <horodatage-ISO> --arm` sur le VPS depuis la copie Git du commit déployé. Le script écrit `/var/lib/serafino-bot/data/stella-expiry.txt`, monté dans le conteneur sous `/app/data/stella-expiry.txt`. Dix jours après l'envoi, les API de chat et voix répondent HTTP 410 ; la page désactive alors la conversation. Créer aussi un rappel pour le même instant, vérifier HTTP 410 et confirmer à Enrico. Avant l'envoi, aucun fichier d'expiration n'est armé.

L'API répond à partir de 15 fiches d'exemples Charte, 11 fiches, dont une vue d’ensemble, qui couvrent systématiquement le cahier des charges officiel et 3 fiches Chef Sera dans `bot/knowledge/`. Les mêmes bases sont intégrées dans la page pour les réponses hors ligne. Chaque fiche distingue critère officiel, conseil opérationnel, fonction vérifiée, simulation ou proposition, avec une source précise. La source normative est [la Charte officielle vaudoise](https://www.vd.ch/fileadmin/user_upload/accueil/fichiers_pdf/2025_janvier_actus/Charte_de_la_restauration_collective_vaudoise.pdf), pages 1–3 ; le document OCDC local `2026_Subventions_alimentation_VD.pdf`, pages 2–3, détaille les moyens de suivi et les subventions.

`node bot/scripts/test-charte-vaud-chat.js` vérifie la synchronisation des fiches, dix questions de couverture, la priorité de la dernière question, les sources, l'origine autorisée et des réponses simulées. Si l'API échoue, la page affiche une fiche hors ligne et le signale. Chrome a été vérifié localement avec une API simulée, y compris les liens de source et une réponse Chef Sera.

Le 13.11.2026, dix scénarios français ont été testés avec `gemini-3.8-flash` et la clé déjà configurée sur le VPS ; les trois cas qui ont révélé un défaut de citation ou de recherche ont été corrigés puis retestés, avec deux autres régressions sur la vue d'ensemble et le statut du pilote. Les réponses couvrent la Charte, les fonctions présentes, la simulation, le pilote, une instruction hostile et une question hors périmètre. La latence observée était d'environ 2,2–3,5 s par appel. Ces quinze appels ont utilisé 12 354 tokens d'entrée et 1 644 tokens de sortie, soit environ 0,0154 USD aux [tarifs annoncés pour Gemini 3.8 Flash jusqu'au 31.12.2026](https://ai.google.dev/gemini-api/docs/pricing) ; le coût exact facturé n'est pas visible dans ces réponses. Aucun paiement n'a été effectué par ce test. Le déploiement du bot est nécessaire pour activer la conversation en ligne ; déployer la seule page ne suffit pas.
